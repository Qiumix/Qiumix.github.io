将helix配置打包进可执行文件

Intro

我们在服务器上的时候，默认的vim/nvim比较难用，我们一般也不会去把自己的配置扒拉下来，毕竟要下载一大堆插件，而且还要给root用户配置一遍。

这时候我们可以把目光放到helix，自带了很多vim/nvim需要插件才能实现的功能，比如picker和gw的easy motion，在几乎无配置的服务器场景很好用。

but，可能我们会遇到无法使用包管理器，或者无法联网，甚至包管理器不提供helix的场景。

另外一个问题是，我们的helix可能也做了很多配置，还要单独把config.toml给scp上去。

这种情况下我们就可以考虑自己魔改AppImage版本的helix了。

Startup

首先通过下列命令下载目前最新的helix的AppImage的releases。

curl https://github.com/helix-editor/helix/releases/download/25.07.1/helix-25.07.1-x86_64.AppImage -o helix -L && chmod +x helix

这里是25.07版本，虽然helix自己说会有26.04版本，但是已经过去半年了还是没有消息，所以这里用25.07。

strings ./helix | grep GLIBC_

返回结果是GLIBC_2.2.5，你可能会想如此老旧的glibc版本需求， 应该和绝大部分x86_64的使用了glibc的linux机器兼容，但其实不是这样，我们稍后讲。

然后我们

./helix --appimage-extract

得到squashfs-root

这时候

strings squashfs-root/usr/bin/hx | grep GLIBC_

GLIBC_2.28
GLIBC_2.16

GLIBC_2.14
GLIBC_2.3
GLIBC_2.3.2
GLIBC_2.27
GLIBC_2.33
GLIBC_2.17
GLIBC_2.18
GLIBC_2.32
GLIBC_2.4
GLIBC_2.5
GLIBC_2.34
GLIBC_2.3.4
GLIBC_2.2.5

会发现需要2.34。

因为AppImage本质是一个自动解压挂载的归档文件，类似Windows的自解压安装包。 实际上会运行的是解压后运行时的解压后二进制。 刚开始grep不到是因为squashfs-root被压缩了。

下一步我们开始打包配置。

把我们的config.toml、languages.toml 和 themes/放到squashfs-root中的某个位置的helix目录下。 这里我放到了squashfs-root/config/helix 然后在AppRun脚本中添加一行

export XDG_CONFIG_HOME="$APPDIR/config"

因为helix遵循XDG目录标准，会从XDG_CONFIG_HOME环境变量读取配置。 而AppRun是AppImage会运行的脚本。

然后我们利用appimagetool重新打包，在arch上需要aur安装。

rm helix && appimagetool squashfs-root/ helix

然后大功告成。

然鹅，这种方法有个问题，XDG_CONFIG_HOME被helix覆盖了，如果helix调用别的工具比如yazi，那么它们的配置文件是空白的。

我们运行下helix --help会发现有单独的--config选项指定config.toml的路径，自己自定义的主题可以直接放到squashfs-root/usr/lib/helix/runtime/themes， 但是没有别的办法指定languages.toml，虽然能用到单二进制helix的场景大概也不需要lsp支持（确信。

把原本squashfs-root/config/helix/config.toml移动到squashfs-root/config/config.toml， 然后squashfs-root/config/helix/themes/下的所有文件迁移到squashfs-root/usr/lib/helix/runtime/themes 然后AppRun改成

#!/bin/sh

APPDIR="$(dirname "$(readlink -f "${0}")")"
HELIX_RUNTIME="$APPDIR/usr/lib/helix/runtime" exec "$APPDIR/usr/bin/hx" "$@" -c "$APPDIR/config/config.toml"

然后

rm helix && appimagetool squashfs-root/ helix

大功告成。

之后我们只需要把需要helix给scp到服务器上然后挪到PATH里的任意位置就可以愉快使用了。

有一点需要注意的是AppImage的运行需要fuse，注意提前安装它的包。

musl用户的话，因为helix需要tree-sitter，强制依赖glibc的动态链接功能， helix官方也回应了不会增加musl支持，所以要自己额外把glibc打包进AppImage里了，我没有尝试过，不过应该也可以用。

同理的话用环境变量大概nvim也可以这么做，不过nvim会读写~/.local/share/nvim下的插件， 需要额外设置个环境变量，还有undofile也是放在这里的，记得关一下相关功能，yanky和snacks之类的插件也会读写…
